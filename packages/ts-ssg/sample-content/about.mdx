## What We Build

We build tooling for docs, product pages, and knowledge portals that need:

- reliable builds in CI/CD,
- high-quality default UX,
- straightforward customization,
- clean separation between content and runtime behavior.

<AlertBox title="Our practical rule" variant="info" tone="default">
  If a feature adds complexity, it must clearly improve maintainability or user
  outcomes. Otherwise, it does not ship.
</AlertBox>

## Team Style

Our team works with a strong bias for clarity:

- explicit naming over clever abstractions,
- small composable building blocks,
- test coverage for behavior changes,
- documentation that explains intent, not just syntax.
