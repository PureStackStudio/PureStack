# AutoCompleteInput

`AutoCompleteInput` keeps the exact `FormInputField` surface while adding a combobox popup, option filtering, keyboard selection, and a named row component hook for custom suggestion layouts.

## 1. Runtime playground

This playground is mounted with `PageScript`, so the fields below are live: type into them, use arrow keys, press Enter, and watch the selected values update.

## 2. Inline options

Use inline options when the suggestion list is known at authoring time. The component keeps normal form attributes like `name`, `required`, `autocomplete`, icons, tone, and variant.

<app id="auto-complete-inline-options"></app>

```html
<AutoCompleteInput
  label="Workspace"
  name="workspace"
  placeholder="Search workspaces"
  icon="lucide:search"
  required="true"
  :model="workspaceQuery"
  :selectedValue="workspaceValue"
  :options="[
    { label: 'Atlas Cloud', value: 'atlas-cloud', keywords: ['enterprise', 'production'] },
    { label: 'Beacon Labs', value: 'beacon-labs', keywords: ['research', 'preview'] },
    { label: 'Compass Ops', value: 'compass-ops', keywords: ['operations', 'incident'] },
    { label: 'Delta Finance', value: 'delta-finance', keywords: ['billing', 'revenue'] },
  ]"
/>
```

## 3. Custom row component by name

The popup appearance is controlled with a component name, not a slot. `AutoCompleteInput` owns combobox behavior; the row component owns visual presentation.

```html
<AutoCompleteInput
  label="Owner"
  name="owner"
  rowComponent="PeopleSuggestionRow"
  :options="peopleOptions"
  @optionselect="assignOwner($event.detail.option)"
/>
```

The row component receives the same structured props for every option.

```ts
defineComponent(
  html`<div class="people-row" :data-active="active">
    <span>{{ option.label }}</span>
    <Badge r-if="selected">Selected</Badge>
  </div>`,
  {
    props: ['option', 'item', 'index', 'query', 'active', 'selected', 'disabled'],
  },
)
```

## 4. Async search pattern

Use `@querychange` for remote or delayed sources. The component shows its loading message while `loading` is true and keeps keyboard behavior consistent when new options arrive.

```html
<AutoCompleteInput
  label="Service"
  :model="serviceQuery"
  :options="serviceOptions"
  :loading="serviceLoading"
  loadingText="Searching services"
  emptyText="No service matches"
  @querychange="searchServices($event.detail.query)"
  @optionselect="selectService($event.detail.option)"
/>
```

## 6. Props reference

```html
<AutoCompleteInput
  label="Field label"
  tone="neutral|accent|info|success|warning|danger|ghost|feature|secondary|custom"
  variant="surfaceAlt|surface|outline|subtle|..."
  name="fieldName"
  type="search|text"
  placeholder="Search..."
  autocomplete="off"
  required="true|false"
  disabled="true|false"
  icon="lucide:search"
  iconEnd="lucide:chevron-down"
  minLength="0"
  maxResults="10"
  openOnFocus="true|false"
  loading="true|false"
  loadingText="Loading suggestions"
  emptyText="No suggestions"
  rowComponent="CustomSuggestionRow"
  :model="queryRef"
  :selectedValue="selectedValueRef"
  :options="[
    { label: 'Visible label', value: 'submitted-value', keywords: ['searchable'], disabled: false },
  ]"
  @querychange="handleSearch($event.detail.query)"
  @optionselect="handleSelect($event.detail.option)"
/>
```
