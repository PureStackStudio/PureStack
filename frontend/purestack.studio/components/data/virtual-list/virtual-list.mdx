## How the window works

VirtualList keeps the full array in memory while mounting a small range of rows. A spacer provides the full scroll distance; a translated window places the mounted rows at their correct positions.

    <h3 class="mt-0">336 pixels tall</h3>
    <p>At 56 pixels per row, six rows fit in the viewport. The outer height stays fixed as the dataset grows.</p>

  <Panel variant="surface" bodyClass="p-3 min-w-0">
    <p class="text-eyebrow">02 · BUFFER</p>
    <h3 class="mt-0">14 mounted rows</h3>
    <p>Overscan 4 adds eight rows to the window budget: six visible rows plus four on either side. Near the boundaries, the range is adjusted.</p>
  </Panel>
  <Panel variant="surface" bodyClass="p-3 min-w-0">
    <p class="text-eyebrow">03 · SCROLL SPACE</p>
    <h3 class="mt-0">560,000 pixels</h3>
    <p>10,000 records × 56 pixels gives the spacer height. This is scroll geometry, not 10,000 mounted row elements.</p>
  </Panel>
</Grid>

The window starts at <code>max(0, floor(scrollTop / itemHeight) - overscan)</code> and mounts up to <code>ceil(height / itemHeight) + 2 × overscan</code> rows, limited by the remaining items. At the top, the unused leading buffer is effectively placed after the visible rows; near the end, fewer rows remain to mount. A partially visible row can also straddle the viewport edge.

## Fixed heights that stay aligned

**The complete row must fit itemHeight, including padding and borders.** VirtualList sets the height of a wrapper around your row component. The examples give the row root height: 100% and box-sizing: border-box, then constrain its content to that box.

- Keep vertical spacing inside the row; external margins are not part of the calculated offset.
- Use a single line or otherwise bounded content. Long release names in the playground truncate and expose their full value through a title attribute.
- Keep itemHeight and the row design in sync when changing density.
- For wrapping descriptions, expandable content or images with changing heights, use [VariableVirtualList](/components/data/variable-virtual-list/).

## Filtering and scroll navigation

Filtering is application code: the playground passes a computed array to items. The row index is its position in that filtered array, while item.id retains the record identity. Search and status changes return the viewport to the top so a shorter result set opens at a useful position.

VirtualList has no public scrollToIndex method. For fixed-height rows, the pixel offset is <code>index × itemHeight</code>. The playground sets scrollTop on its own viewport and dispatches a scroll event to synchronize the component immediately. Jump positions are clamped to the matching dataset; the browser also clamps the final offset to the maximum scroll distance.

The search, filters and jump controls do not load data from a server. Virtualization reduces mounted DOM; it does not reduce the memory occupied by the source array or make filtering an array free. Combine it with your own data-loading strategy when needed.

## Read the mounted window

The source array stays in memory; only nearby records become DOM rows. These components have no tone or variant props. Style the viewport and row components, and use semantic tones on their contents, as the live examples do.

## Feature map

| Public feature | Visible behavior |
| --- | --- |
| items | Load 100 to 50,000 records; filter them or empty the dataset. |
| height | Choose a viewport height and compare the mounted-row count. |
| itemHeight | Switch row density and compare scrolling distances; row content must fit the fixed height. |
| overscan | Change the buffer and watch how many extra rows are mounted. |
| rowComponent | The live example registers a named row that receives item and the current array index. |
| Native attributes and events | The viewport is a named, focusable scrolling region. Keyboard scrolling uses browser behavior. |
| Durable state | The persistent-checkbox example keeps selection on the record after a row unmounts. |
| Empty feedback | Empty the dataset or enter a search with no matches; feedback is composed outside the virtual rows. |

## Behavior and accessibility

- **Keyboard scrolling:** the examples add tabindex="0" to the viewport. Arrow keys and Page Up / Page Down scroll the focused container using browser behavior. VirtualList does not add listbox selection or roving focus.
- **List semantics:** provide role="list", a meaningful accessible name and role="listitem" on the row root. Rows can expose aria-posinset using index + 1; the basic example also supplies the known total through aria-setsize.
- **Durable state:** store selections and edits in application data keyed by a stable record identity. Rows outside the mounted range are removed; local row state and focused controls can disappear with them.
- **Complete access:** browser find, printing and assistive navigation only see mounted content. Provide search or an alternative full-data view or export when users need to inspect the whole collection.
- **Empty results:** an empty array produces no rows and a zero-height spacer inside the configured viewport. Compose your own empty message, as both interactive examples do.

### Data and rendering

<ApiProperty anchor="virtual-list-prop-items" name="items" valueType="RefOrValue&lt;unknown[]&gt;" defaultValue="[]">
  <p>The complete array for this list. Only the current window is mounted; the whole array stays in memory. A missing or non-array value resolves to an empty array. Bind a ref or computed array for replacement and filtering. Preserve durable state on the records or in an external store.</p>
</ApiProperty>

<ApiProperty anchor="virtual-list-prop-rowComponent" name="rowComponent" valueType="RefOrValue&lt;string&gt;" defaultValue="div">
  <p>Name of a component registered in the Regor app. Each mounted instance receives item and the absolute zero-based index in the current items array. Declare both in the row’s props list. The default div does not render the item as text; supply an explicit row renderer.</p>
</ApiProperty>

### Viewport and row geometry

<ApiProperty anchor="virtual-list-prop-height" name="height" valueType="RefOrValue&lt;number | string&gt;" defaultValue="560">
  <p>Viewport height in pixels. Accepts a positive number or numeric string; invalid, non-finite and non-positive values fall back to 560. This is not a CSS length API: use 320, not 20rem or 100%. Changing it recalculates the mounted window.</p>
</ApiProperty>

<ApiProperty anchor="virtual-list-prop-itemHeight" name="itemHeight" valueType="RefOrValue&lt;number | string&gt;" defaultValue="44">
  <p>Fixed height of every item wrapper, in pixels. It determines offsets, spacer height and the window size. Invalid or non-positive values fall back to 44. The component does not measure or clip overflowing row content; size the full row, including padding and borders, to fit.</p>
</ApiProperty>

<ApiProperty anchor="virtual-list-prop-overscan" name="overscan" valueType="RefOrValue&lt;number | string&gt;" defaultValue="6">
  <p>Buffer used before the visible start and twice in the total window budget. Higher values keep more rows mounted during scrolling at the cost of more DOM. Use a positive integer; positive fractions are truncated. Zero, negative and invalid values fall back to 6, so passing zero does not disable overscan.</p>
</ApiProperty>

### Row component contract

```typescript
import type { RefOrValue } from 'regor'

interface RecordRow {
  item: RefOrValue<ReleaseRecord>
  index: RefOrValue<number>
}
```

Use your own record type in place of ReleaseRecord. The index is absolute within the current items array, not relative to the mounted window. After filtering or reordering, it can change for the same item; use a stable field such as item.id for application identity and input IDs. The basic and persistent-state sources show complete definitions and registration.

### Composition and limits

<div class="api-contract">
  <p>Register defineVirtualListComponents and your named row component. VirtualList has no slots, built-in header, footer, empty state, selection model or data fetcher. Compose these outside the viewport. It does not forward arbitrary parent props to rows; include row-specific data on each item or use application context.</p>
</div>

The exported interface includes internal computed fields and a scroll handler for implementation use. Only the five registered props above form the public template API; scrollTop is not a two-way component prop.
