## How the table window works

The component renders a real table. Spacer rows before and after the mounted data rows preserve the scroll distance; the header, footer and column group remain outside the virtualized data window.

<Grid columns="1" columnsMd="3">
  <Panel variant="surface" bodyClass="p-3 min-w-0"><p class="text-eyebrow">DATA</p><h3 class="mt-0">10,000 records</h3><p>The whole source array remains in memory. Filtering and sorting are application operations performed before passing items.</p></Panel>
  <Panel variant="surface" bodyClass="p-3 min-w-0"><p class="text-eyebrow">WINDOW</p><h3 class="mt-0">16 data rows</h3><p>At a 360-pixel viewport, 48-pixel rows and overscan 4, the window budget is ceil(360 / 48) + 8. Fewer rows remain near the end.</p></Panel>
  <Panel variant="surface" bodyClass="p-3 min-w-0"><p class="text-eyebrow">GEOMETRY</p><h3 class="mt-0">48 pixels each</h3><p>Data-row offsets come from itemHeight. Header and footer sections also occupy space in the native table.</p></Panel>
</Grid>

The start index is <code>max(0, floor(scrollTop / itemHeight) - overscan)</code>. The budget is <code>ceil(height / itemHeight) + 2 × overscan</code>, limited by the remaining items. It uses the viewport height, not the area left after sticky sections, so mounted and actually visible counts differ.

## Keeping fixed rows fixed

HTML table row height is a minimum: content can force a row to grow. Keep cell content to a bounded line and fit padding, borders, badges and controls inside itemHeight. The playground uses zero vertical cell padding and single-line content. Fixed-layout release titles truncate and expose their full text through a title attribute.

Wrapping descriptions or expandable details need [VariableVirtualTable](/components/data/variable-virtual-table/). Increasing overscan cannot repair incorrect fixed-height geometry.

## Filtering, sorting and navigation

The example derives items with a computed filter and sort, then resets scrollTop when that sequence changes. Position means index in the current matching array; item.id remains the stable record identity. Sorting does not mutate the source array.

The jump control sets the viewport scrollTop to <code>(position - 1) × itemHeight</code> and dispatches a scroll event for immediate synchronization. The browser clamps the final offset. Header and footer geometry affect exact visual alignment; this is application code, not a public scrollToIndex method.

## Composing a real table

| Component prop | Root element | Purpose |
| --- | --- | --- |
| rowComponent | tr | Receives item and index; render td or th cells. |
| colGroupComponent | colgroup | Contains col elements that guide column widths. |
| headerComponent | thead | Contains header rows and th cells with scope="col". |
| footerComponent | tfoot | Contains summary rows; colspan must match your columns. |

Each part is explicitly defined and registered in the example file. Header, footer and column-group components receive no item or index props. For a dynamic summary, supply application context to your own footer; the virtual table does not calculate aggregates.

The existing theme makes the header sticky at the top and footer cells sticky at the bottom. Give those cells a surface background so scrolling content does not show through. Only data rows are virtualized; keep the surrounding sections compact.

Auto layout sizes the table from content and uses a minimum width of 100%; widths may shift as different rows mount. Fixed layout uses width: 100% with table-layout: fixed. A column group makes the intended widths explicit. Toggle both modes in the playground; oversized cell content can still require horizontal scrolling.

## Read the mounted window

The source array stays in memory; only nearby records become DOM rows. These components have no tone or variant props. Style the viewport and row components, and use semantic tones on their contents, as the live examples do.

## Feature map

| Public feature | Visible behavior |
| --- | --- |
| items | Load 100 to 50,000 records; filter and sort them or empty the dataset. |
| height | Choose a viewport height and compare the mounted-row count. |
| itemHeight | Switch row density and compare scrolling distances; row content must fit the fixed height. |
| overscan | Change the buffer and watch how many extra rows are mounted. |
| rowComponent | The live example registers a named row that receives item and the current array index. |
| headerComponent and footerComponent | Toggle each section; both use valid native table roots and remain sticky. |
| colGroupComponent | Toggle explicit widths and compare horizontal scrolling inside the viewport. |
| tableLayout | Compare auto and fixed column sizing in the live editor. |
| Native attributes and events | The viewport is a named, focusable scrolling region. Keyboard scrolling uses browser behavior. |
| Durable state | Sorting and filtering operate on the same records; use a stable record ID for durable application state. |
| Empty feedback | Empty the dataset or enter a search with no matches; feedback is composed outside the virtual rows. |

## Behavior and accessibility

- **Keyboard scrolling:** the examples add tabindex="0" to the viewport. Arrow keys and Page Up / Page Down use native browser scrolling. These components do not implement spreadsheet navigation or roving focus.
- **Table semantics:** render valid table sections and scoped column headers. The examples name the scrollable region; attributes on the component root target that outer div, not the inner table. This is a native table, not an ARIA grid.
- **State and focus:** keep durable state on records or in an external store, keyed by stable identity. A row outside the mounted window is removed, including any focused control inside it.
- **Empty results:** compose a message outside the virtual content. Header and footer sections can remain when the items array is empty.
- **Complete data access:** browser find, printing and assistive navigation only see mounted rows. Provide application search or a full-data view or export where complete access is needed.
- **Memory and loading:** virtualization reduces mounted DOM, not the source array or filtering cost. Data fetching, pagination, selection and sorting remain application responsibilities.

### Data

<ApiProperty anchor="virtual-table-prop-items" name="items" valueType="RefOrValue&lt;unknown[]&gt;" defaultValue="[]">
  <p>The complete source array. Only a window is mounted; all records remain in memory. Bind a ref or computed array to replace, filter or sort it. Non-array values resolve to an empty array.</p>
</ApiProperty>

### Viewport and window

<ApiProperty anchor="virtual-table-prop-height" name="height" valueType="RefOrValue&lt;number | string&gt;" defaultValue="560">
  <p>Viewport height in pixels. Positive numbers and numeric strings are accepted; invalid, non-finite and non-positive values fall back to 560. Use pixel values, not CSS units such as rem or %. This controls the viewport, not a row.</p>
</ApiProperty>

<ApiProperty anchor="virtual-table-prop-itemHeight" name="itemHeight" valueType="RefOrValue&lt;number | string&gt;" defaultValue="44">
  <p>Height used for every data-row offset and spacer calculation, in pixels. Defaults to 44 when invalid or non-positive. Native table content can force rows taller: keep cell content, padding and borders within this height. It does not measure rows.</p>
</ApiProperty>

<ApiProperty anchor="virtual-table-prop-overscan" name="overscan" valueType="RefOrValue&lt;number | string&gt;" defaultValue="6">
  <p>Buffer subtracted from the visible start and added twice to the total window budget. Larger values mount more data rows. Use a positive integer; positive fractions truncate, while zero, negative and invalid values fall back to 6.</p>
</ApiProperty>

### Table component registration

<ApiProperty anchor="virtual-table-prop-rowComponent" name="rowComponent" valueType="RefOrValue&lt;string&gt;" defaultValue="not set">
  <p>Registered component name for each data row. It receives item and the absolute zero-based index in the current items array. Its root must be tr with valid cells. No automatic item formatting is provided.</p>
</ApiProperty>

<ApiProperty anchor="virtual-table-prop-colGroupComponent" name="colGroupComponent" valueType="RefOrValue&lt;string&gt;" defaultValue="not set">
  <p>Optional registered component with a colgroup root and col children. It receives no row props. Use it to describe column widths, together with an appropriate content layout.</p>
</ApiProperty>

<ApiProperty anchor="virtual-table-prop-headerComponent" name="headerComponent" valueType="RefOrValue&lt;string&gt;" defaultValue="not set">
  <p>Optional registered component with a thead root, tr rows and scoped th cells. It receives no row props. Theme styles make the header sticky; give header cells an opaque surface background.</p>
</ApiProperty>

<ApiProperty anchor="virtual-table-prop-footerComponent" name="footerComponent" valueType="RefOrValue&lt;string&gt;" defaultValue="not set">
  <p>Optional registered component with a tfoot root and valid rows and cells. Footer cells are sticky at the bottom under the theme styles. Supply your own content or application context; no automatic aggregates or row props are passed.</p>
</ApiProperty>

### Column layout

<ApiProperty anchor="virtual-table-prop-tableLayout" name="tableLayout" valueType="RefOrValue&lt;'auto' | 'fixed'&gt;" defaultValue="auto">
  <p>auto creates a content-sized table with min-width: 100%; fixed uses a 100%-wide table and fixed column layout. Use a column group for explicit widths. This changes column sizing, not virtual row-height calculation.</p>
</ApiProperty>

### Row contract

```typescript
import type { RefOrValue } from 'regor'

interface ExampleRow {
  item: RefOrValue<YourRecord>
  index: RefOrValue<number>
}
```

Replace YourRecord with your application type and declare item and index in the component's props list. Index is a position in the current array, not a stable identity. The examples define exported interfaces, named templates and explicit registrations in their own TypeScript files.
