# Consent

<ComponentHeader
  name="Consent"
  kind="Privacy preferences"
  summary="Let visitors choose which optional cookies and services your site may use, and change their preferences later."
  source="https://github.com/PureStackStudio/PureStack/blob/main/packages/ts-components/src/standard/consent/consent.ts"

Consent gives visitors control over optional cookies and services, such as
analytics or marketing. Its banner offers **Accept all**, **Reject non-essential**,
and **Manage preferences**. The preferences panel lets visitors choose individual
categories while required categories stay enabled.

Consent remembers the saved choice and loads configured optional services only
after permission is granted. Visitors can reopen preferences using either option
above, change their choices, and save again.

## Open privacy preferences

With consent enabled in your site configuration, Consent is included
automatically. Choose either of these two ways to let visitors reopen their
preferences after making a choice.

### 1. Use your own button or link

Add `data-consent-action="open-panel"` to a `Btn` or `BtnLink` in your footer,
navigation, or page content. Clicking it opens the privacy preferences panel.

For a button:

```html
<Btn tone="neutral" variant="outline" data-consent-action="open-panel">
  Manage privacy settings
</Btn>
```

For a link:

```html
<BtnLink
  href="/legal/privacy/"
  tone="neutral"
  variant="link"
  data-consent-action="open-panel"
>
  Privacy settings
</BtnLink>
```

### 2. Use the default teleport area

Place this empty element where you want the default **Privacy settings** button
to appear:

```html
<span class="consent-settings-teleport-area"></span>
```

Consent automatically places its settings button inside that element.
SiteFooter already provides this area. If the area is absent, Consent does not
add a settings button.

## Configuration

| Configuration | Visible role |
| --- | --- |
| enabled | Determines whether the component renders. |
| storageKey, policyVersion | Set where choices are saved and when visitors must make a fresh choice. |
| categories | Give each category an ID, label, description, and required flag. |
| services | Associate each optional service with the category that gives it permission to load. |
| Banner, action, and settings labels | Customize the language of the banner, buttons, and preferences. |
| privacyPolicyUrl, privacyPolicyLabel | Add the policy destination beside the banner copy. |

Keep category labels and descriptions specific to the services your site uses.

  name="tone"
  valueType="RefOrValue&lt;SemanticTone&gt;"
  defaultValue="neutral"
>
  <p>
    Semantic intent: neutral, accent, secondary, info, success, warning, danger,
    feature, custom or ghost. The active skin supplies the colors.
  </p>
</ApiProperty>

<ApiProperty
  anchor="consent-prop-variant"
  name="variant"
  valueType="RefOrValue&lt;ComponentVariant&gt;"
  defaultValue="surfaceAlt"
>
  <p>
    Visual treatment. Accepts solid, surface, surfaceAlt, spotlight, glass,
    flat, flatAlt, flatSolid, outlineFill, outline, subtle, subtleBtn, link,
    sheen, underline, rail, bracket or none.
  </p>
</ApiProperty>

<ApiProperty
  anchor="consent-prop-variantMode"
  name="variantMode"
  valueType="RefOrValue&lt;ComponentVariantMode&gt;"
  defaultValue="stateless"
>
  <p>
    Use stateless for content surfaces; stateful enables the treatment’s hover,
    focus and active styles. It does not add interaction handlers.
  </p>
</ApiProperty>

<ApiProperty
  anchor="consent-prop-settingsTeleport"
  name="settingsTeleport"
  valueType="string"
  defaultValue=".consent-settings-teleport-area"
>
  <p>
    CSS selector for the built-in settings button's destination. Provide the
    target before Consent renders. An empty selector or a missing target omits
    the button; the banner and preference panel remain available.
  </p>
</ApiProperty>
