## Usage

Use `Btn` for an action and `BtnLink` for navigation. Both are available directly in PureStack MDX. A `Btn` renders a native `button`; a `BtnLink` renders an anchor with a real `href`.

<Panel tone="info" variant="surface">
  <strong>Static markup. Explicit interaction.</strong>
  <p>MDX renders components at build time. Mount a Regor app through <code>PageScript</code> or <code>RegorApp</code> when a button needs browser state or an event handler. The interaction example below shows both the markup and browser code.</p>
</Panel>

## Browser interaction

Click to add items, then reset the collection. The count belongs to this mounted example and survives opening or closing its source panel.

<Panel tone="neutral" variant="surface">
<div data-doc-demo="button-events"><DocsButtonEvents/></div>
</Panel>

<details>
<summary>View source</summary>

```html
<Flex direction="column" align="center">
  <Btn tone="accent" @click="increment">Add to collection</Btn>
  <p role="status">Your collection has <strong r-text="count"></strong> items.</p>
  <Btn variant="link" tone="neutral" @click="resetCount">Reset collection</Btn>
</Flex>
```

Save the browser code as `collection.ts` beside your MDX page. Add a mount point and load it with `PageScript`:

```html
<div id="collection"></div>
<PageScript src="./collection.ts"/>
```

**collection.ts**

```typescript
import { createApp, html, ref } from 'regor'
import { defineButtonComponents, defineFlexComponents } from '@purestack/ts-components'

const count = ref(0)
const increment = () => count(count() + 1)
const resetCount = () => count(0)

createApp({
  count, increment, resetCount,
  components: { ...defineButtonComponents(), ...defineFlexComponents() },
}, {
  selector: '#collection',
  template: html`<Flex direction="column" align="center">
    <Btn tone="accent" @click="increment">Add to collection</Btn>
    <p role="status">Your collection has <strong r-text="count"></strong> items.</p>
    <Btn variant="link" tone="neutral" @click="resetCount">Reset collection</Btn>
  </Flex>`,
})
```

</details>

### Submit and reset

The default button type is `button`. Choose `submit` or `reset` explicitly inside a form. This sample validates the required field and handles submission locally.

The form handles `@reset.prevent` so its reactive value stays synchronized with the input instead of being overwritten by the browser’s native reset.

<Panel tone="neutral" variant="surface">
<div data-doc-demo="button-form"><DocsButtonForm/></div>
</Panel>

<details>
<summary>View source</summary>

```html
<form @submit.prevent="submit" @reset.prevent="resetForm">
  <FormInputField id="demo-project-name" label="Project name" :model="project" name="project" :required="true"/>
  <Flex><Btn type="submit" tone="accent">Save project</Btn><Btn type="reset" variant="surface" tone="neutral">Reset</Btn></Flex>
  <p role="status" r-text="message"></p>
</form>
```

**Browser TypeScript**

```typescript
const project = ref('My next idea')
const message = ref('Changes stay in this demo.')
const submit = () => message(`Saved “${project()}”.`)
const resetForm = () => {
  project('My next idea')
  message('Form reset.')
}
// Pass these bindings into createApp with defineFormInputField(),
// defineButtonComponents(), and defineFlexComponents().
```

</details>

## Accessibility

- Use a visible, specific label such as “Save project”.
- Give icon-only controls an accessible name with `ariaLabel`.
- A disabled button cannot be activated or reached with Tab. Use visible context to explain why an action is unavailable.
- Keep navigation as links, including links styled as buttons.
- Use bound booleans such as `:disabled="false"` when supplying boolean values through MDX.

## API reference

The tables list author-facing props, slots, and events. Props accept their value or a Regor ref where declared by the component. Computed implementation fields are internal.

### Shared props · Btn and BtnLink

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `tone` | `SemanticTone` | neutral (inherited) | neutral · accent · feature · secondary · custom · ghost · info · success · warning · danger |
| `variant` | `ComponentVariant` | solid | solid · surface · surfaceAlt · outlineFill · outline · subtle · subtleBtn · link · sheen · underline · rail · bracket · none |
| `size` | `'sm' \| 'md' \| 'lg'` | md | Uses the current theme’s font scale. |
| `icon` | `string` | — | A registered provider:icon-name. |
| `iconPosition` | `'start' \| 'end'` | start | Places the icon before or after the label. |
| `iconOnly` | `boolean` | false | Hides the default slot. Supply an icon and ariaLabel. |
| `ariaLabel` | `string` | — | Accessible name. Required when no visible label is present. |

### Btn

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `'button' \| 'submit' \| 'reset'` | button | The native button type. |
| `disabled` | `boolean` | false | Native disabled state; removes the button from keyboard focus and blocks activation. |

### BtnLink

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `href` | `string` | — | Destination URL. Normalized through the SSG’s public/base-path resolver when available. |
| `target` | `string` | — | Native anchor target, such as _blank. |
| `rel` | `string` | automatic for _blank | Defaults to noopener noreferrer for _blank. An explicit rel takes precedence. |

### Slots and events

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `default` | `slot` | — | Button or link label. Hidden when iconOnly is true. |
| `@click` | `MouseEvent` | — | A browser event. Attach a handler in a mounted Regor application. |
| `class / data-* / aria-*` | `native attributes` | — | Additional attributes inherit onto the button or anchor. |
