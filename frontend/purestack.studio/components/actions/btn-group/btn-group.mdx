# BtnGroup

<ComponentHeader name="BtnGroup" kind="Action layout" summary="Related actions, one coherent row. Control alignment and wrapping while every child keeps its own identity." source="https://github.com/PureStackStudio/PureStack/blob/main/packages/ts-components/src/standard/btnGroup/btnGroup.ts"/>

Use it for action rows, navigation choices, or a small set of formatting controls. Its two layout props work with [Btn](/components/actions/buttons/), [BtnLink](/components/actions/btn-link/), and other controls in the default slot.

## Accessibility

- Use `role="group"` with a meaningful `aria-label` or `aria-labelledby` when the relationship between the controls needs a name. BtnGroup renders a plain `div` by default.
- Each child keeps its native keyboard behavior: Tab moves among controls, Enter follows links, and Enter or Space activates buttons.
- Use `aria-pressed` on toggle buttons, as in the formatting example. The group does not manage selection.
- Keep DOM order aligned with reading order. Wrapping changes the layout while preserving the order of the controls.
- A group is not an ARIA toolbar. Adding `role="toolbar"` also requires implementing the expected toolbar keyboard behavior; BtnGroup does not supply arrow-key navigation or a roving tab stop.
- If you intentionally keep a wide row, make its scroll container keyboard-accessible and give it a meaningful name.

<ApiProperty anchor="group-prop-align" name="align" valueType="BtnGroupAlign" defaultValue="start (base alignment)">
  <p>Aligns the children within the group. The default stylesheet uses start alignment. A content-sized group has no extra space to distribute; give it width when using center or end alignment.</p>
  <div class="api-values"><code>start</code><code>center</code><code>end</code></div>
  <div class="api-demo">

<ApiProperty anchor="group-prop-wrap" name="wrap" valueType="boolean" defaultValue="false">
  <p>Allows children to flow onto another line when space is limited. Omission keeps a single row. Wrapping needs a constrained available width to become visible.</p>
  <div class="api-values"><code>false · single row</code><code>true · multiple rows</code></div>

### Slots and native attributes

<div class="api-contract">
  <h4>Default slot</h4>
  <p>Related controls rendered in source order. Each direct child is a flex item. Buttons and links keep their own props, accessible names, and native behavior.</p>
  <h4>Native attributes</h4>
  <p><code>class</code>, <code>id</code>, <code>role</code>, and ARIA attributes reach the root <code>div</code>. Use <code>class="w-full"</code> for an action row that fills its container.</p>
  <h4>Scope</h4>
  <p>The two public props are <code>align</code> and <code>wrap</code>. Dropdown menus are provided by the separate <a href="/components/actions/btn-group-drop-down/">BtnGroupDropDown</a> component.</p>
</div>

```html
<BtnGroup :wrap="true" role="group" aria-label="Documentation navigation">
  <BtnLink href="/components/actions/buttons/">Buttons</BtnLink>
  <BtnLink href="/components/actions/badge/" variant="surface">Badge</BtnLink>
</BtnGroup>
```

### State and events

BtnGroup adds no selection model, group-disabled state, or custom events. Attach action handlers and state to its children. Native events may bubble to the group as usual.

The [formatting controls](#formatting-controls) show complete reactive code, including `computed` variant refs, native `aria-pressed`, and individual click handlers. Use that pattern when a child's appearance follows application state.

For child props, see [Buttons](/components/actions/buttons/) and [BtnLink](/components/actions/btn-link/).
