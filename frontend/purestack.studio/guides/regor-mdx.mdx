# Write Regor MDX

An `.mdx` or `.rmdx` page combines Markdown with registered Regor components. Use Markdown for prose, lists, tables, and code. Use components for structured UI that should share the site's theme.

## Compose a page

```mdx
---
title: Project guide
description: The first steps for a new project.
template: doc
---

# Project guide

Start with the content your reader needs.

<Panel tone="info" bodyClass="p-3">
  <h2 class="mt-0">Before you begin</h2>
  <p>Keep your site configuration beside the content folder.</p>
  <BtnLink href="/guides/purestack-cli/" tone="info" variant="link">Set up the site</BtnLink>
</Panel>
```

`Panel` and `BtnLink` are built-in components. Components registered by a site runner can also be used in its MDX pages. The [component catalog](/components/) shows their props and live examples.

The [VS Code extension](/guides/vscode-extension/) helps with component props, frontmatter, and markup while you write.

## Keep content and behavior separate

Components in an MDX page are rendered to HTML during the build. Their Regor state and event handlers do not automatically start in the browser. Use [RegorApp](/components/runtime/regor-app/) for an interactive mount or [PageScript](/components/runtime/page-script/) for a focused browser script.

Use ordinary headings in reading order. The doc template extracts second- and third-level headings for the page outline, while frontmatter controls the page title, description, template, and navigation order.

## Link between routes

Use root-relative URLs for site pages, such as `/guides/themes/`. The generator produces folder routes, so each content page gets a stable trailing-slash destination. Keep related source files near the page that uses them.
